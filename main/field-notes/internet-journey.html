04 / NETWORKS IN MOTION

A web request
takes a little journey.

Typing a website's name feels like one action. Underneath, your device asks a chain of questions, sends packets through several networks, and assembles a response into a page.

FIRST / FIND THE ADDRESS

DNS looks up a name.

A computer sends data using numeric IP addresses, while people prefer names such as lvwebsite.com. The Domain Name System (DNS) helps translate a name into the records needed to reach a service. Your browser, operating system, home router, or DNS provider may already have a cached answer, so a lookup is not necessarily repeated for every visit.

The answer can depend on the type of record requested, the resolver, caching, and how a site distributes traffic. DNS helps find an endpoint; it does not prove the endpoint is trustworthy or encrypt the content by itself.

NEXT / MOVE PACKETS

Routers pass traffic between networks.

Your device checks whether the destination is on the local network. If not, it sends packets to a gateway—usually your router—which forwards them toward the internet service provider. Networks exchange routing information to decide where traffic should go next. The path can cross many independent networks, and the route taken may change over time.

Packets are pieces of data with addressing and control information. They may take different paths and be reassembled at the destination. The home Wi-Fi link is only the first hop; a perfect Wi-Fi signal cannot fix a distant server outage or an upstream routing problem.

THEN / ESTABLISH THE SESSION

HTTPS protects the conversation in transit.

For an HTTPS connection, the browser and server negotiate encrypted transport and check a certificate to authenticate the server name. Modern HTTPS commonly uses TLS over TCP, while HTTP/3 uses QUIC over UDP. The precise details depend on the browser, server, and network.

Encryption helps prevent intermediaries from reading or changing the protected content in transit, but it does not make a website automatically safe. It cannot tell whether you chose a misleading site, whether an account is secure, or what the service does with data after it receives it. Check the hostname and use good account security as well.

FINALLY / BUILD THE PAGE

The response becomes pixels.

The browser sends an HTTP request. A web server or application returns a response that might include HTML, stylesheets, scripts, images, and other resources. The browser parses the HTML, requests referenced files, applies styles, runs scripts, lays out elements, and paints the visible result. A page may make many requests, and caching can reduce the work on later visits.

When something fails, locate the stage: Does the hostname resolve? Can other sites load? Is the server responding? Does only one file fail? Browser developer tools can show request status, timing, and console errors. On a local network, basic tools such as ping, tracert/traceroute, and nslookup can add clues, though firewalls may block some probes.
